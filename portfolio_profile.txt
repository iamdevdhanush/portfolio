PROJECT: GreenOps
--------------------------------------------------
Project Type: Distributed infrastructure / machine monitoring platform
Status: Listed on current site
Repository: https://github.com/iamdevdhanush/greenops
Live Demo: None listed
Date/Year: Not stated

ONE-LINE DESCRIPTION:
A distributed monitoring platform for telemetry ingestion, heartbeat tracking,
and energy consumption analytics.

PROBLEM:
Infrastructure monitoring tools often lack energy awareness and are too complex
for small to medium deployments; there is a need for a lightweight,
energy-conscious monitoring solution.

SOLUTION:
Agent-server architecture where machines register automatically and stream
telemetry to a FastAPI backend that tracks heartbeats, machine states, and
energy usage, exposed through a JWT-authenticated API and containerized with
Docker.

KEY FEATURES:
- Distributed telemetry ingestion with concurrent stream handling
- Real-time heartbeat monitoring and alerting
- Energy consumption dashboards and analytics
- JWT-authenticated REST API
- Docker-based deployment and scaling

TECHNOLOGIES ACTUALLY USED:
- Python, FastAPI, PostgreSQL, Docker, JWT

ARCHITECTURE / TECHNICAL DETAILS (from resume 1 + 2 + site):
- Agent-server architecture; machines auto-register using hardware fingerprint
  and authenticated tokens (resume 1)
- 60-second heartbeat monitoring with timeout-based offline detection handling
  intermittent network loss (resume 1)
- Machine lifecycle state tracking: ACTIVE / IDLE / OFFLINE from persisted
  heartbeat timestamps (resume 1 + 2)
- Inactivity analysis estimating energy wastage from idle duration intervals
  (resume 1)
- Normalized PostgreSQL schema for high-frequency time-series telemetry writes
  (resume 2)
- Energy and uptime monitoring via SQL aggregation over telemetry data
  (resume 2)
- JWT authentication middleware securing agent communication (resume 2)
- Docker Compose one-command deployment of backend + database (resume 2)
- Multi-stage Docker builds (site project data)

AI / ML COMPONENT: None.

BACKEND: FastAPI; JWT middleware; telemetry ingestion + heartbeat APIs.

FRONTEND: None described (site lists "energy consumption dashboards"; no
frontend framework named).

DEPLOYMENT: Docker / Docker Compose containerized stack.

NOTABLE TECHNICAL WORK:
- Handling concurrent telemetry streams from hundreds of distributed agents
  (challenge listed)
- Efficient time-series storage design for energy analytics
- Secure authentication without performance compromise

MEASURABLE RESULTS: None stated.
